# 福利兑换限领（2026-10-23）

## 已确认需求与验收
- 按活动、站内账号限制成功兑换的码数，余额码和抽奖券码共享额度；默认 1 次，可创建时设置、创建后修改。
- 生成时可不参加活动、选择已有活动补发；可管理活动名称和限额。活动内部信息仅管理员可见。
- 失败不占额度、不消耗码；并发不能超领；删除已用码不恢复额度；不同活动互不影响。
- 调高限额允许继续领取；调低不撤回已发权益。旧码、充值履约接口保持兼容。

## 实现与影响面
1. 新增 redeem_campaigns、redeem_campaign_claims 表和 redeem_codes.campaign_id 可空字段；Ent schema 和生成代码同步。活动不提供删除、兑换码活动归属创建后不可改。
2. 复用 RedeemCodeRepository 的附加接口模式（现有 RedeemTicketGranter）；管理活动使用 RedeemService，生成使用 adminService.GenerateRedeemCodes，二者校验活动关联类型和值。
3. 兑换在已有事务中锁活动配置 FOR SHARE，再原子 UPSERT 领取计数；与 Use 和权益发放一起提交或回滚。修改配置由 UPDATE 取得排他锁。数据库异常时拒绝受限码，不依赖 Redis。
4. 管理端兑换码页增加活动入口、分页列表/新增/编辑，以及生成时活动选择；列表显示活动。用户端只新增本地化限领错误，不披露内部活动名称。
5. 测试覆盖：输入校验、真实 HTTP 入口、共享额度、不同用户/活动、调大/调小、删除不重置、失败回滚、并发；前端生成及编辑交互、i18n、类型检查、构建、截图。

## 风险与回退
- 用户已确认“按照建议来、次数可改”，授权本次本地实现及迁移文件；不接触生产、不提交/推送/部署。
- 迁移仅新增可空字段和独立表，不追溯旧码、不批量改历史数据。回退先停止活动码兑换并备份表，再回旧应用；保留新表/字段及领取记录。显式删除结构的 SQL 放交付文档，禁止自动执行。
- 活动限额 1–1000 次，名称 1–100 字符。活动列表分页，每页最大 100；生成数量沿用接口 1–100。
- 不引依赖；Go/Ent、Vue/TypeScript、项目既有事务、幂等和分页风格。活动写入走管理员鉴权和既有幂等包装。
