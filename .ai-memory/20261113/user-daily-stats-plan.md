# 用户每日统计

日期：2026-11-13。分支：feature/user-daily-stats，基线 3ee90ee51。

## 目标与边界

- Go/Gin/PostgreSQL + Vue/TypeScript；新增独立管理员只读统计页及列表、活动明细两个 GET 接口。
- 复用管理员认证、已有 users/checkin_records/zenxiang_liyu_records/usage_logs/wallet_transactions；不改变发奖、消费和权限规则，不增加迁移，不访问生产账目。
- 按 Asia/Shanghai 自然日，默认今天，比较选定日与前一日；余额明确是查询时当前余额，非历史日末快照。
- 当天消费按实际费用排序，在全站计算名次后才搜索／筛选；无消费不排名。保留现有排行榜的费用、Token、用户ID排序规则。
- 消费区分充值、签到／礼遇／赠送福利、订阅和未分账；历史与未结算消费不猜测拆分。排行和汇总使用同一查询快照，分页不改变汇总。
- 活动按基础领取／抽奖日期及翻倍／猜大小实际发生时间分别汇总，跨日输赢不会回写原抽奖日统计。抽奖券面额单列，不能当成现金成本；活动净收益不等同福利实际核销。
- 汇总用户数、活跃／签到／抽奖人数、活动收益、前后日消费、分来源扣款、请求／Token、当前充值／福利及来源、冻结、管理员赠送及其他福利调整。分页、搜索、活动筛选、排序、活动明细、使用记录跳转、当前页CSV。

## 设计与风险

- 选择独立 Repository→Service→Handler，Wire 接线；避免扩张签到写业务或在前端逐用户请求。
- 限定两日用量扫描；各来源先独立聚合再关联用户，避免多对多金额膨胀；SQL使用参数与排序白名单，列表最多100项、查询超时。
- 单条SQL包含全局排名、过滤汇总、分页与JSON结果，保证越界页也有汇总；不以缓存推断金额。活动明细单独按用户分页。
- 新路由沿用管理认证，受限管理员密钥默认拒绝未知路由；不扩展其允许列表。
- 实时余额与活动更新会令不同请求时点变化；页面显示生成时间。历史活动可能属于旧充值类奖励，活动净收益与消费福利分账分别展示。
- 回退：撤回本分支前后端文件即可，无数据结构或业务数据变更。数据库性能若存在问题停留在本地验证，不部署。
