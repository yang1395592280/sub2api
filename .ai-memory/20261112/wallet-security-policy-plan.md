# 福利消费安全与可配置比例

基线：feature/refund-welfare-display，保留上一轮未提交退款与展示修复。不发布、不操作生产数据。

## 口径与不变量
- 福利净额 = 签到 + 礼遇 + 管理员赠送。净额 <= 0 时全扣充值；净额 > 0 时消费福利总扣款不得超过净正额，也不得扣减单个负来源。
- 活动失败仍可形成对应来源负债，后续奖励还债；充值不负责清偿福利负债。
- 管理员配置充值份额 : 福利份额，默认 2:1；充值份额必须 > 0，福利份额可为 0，整数有界。无正充值不能仅用福利消费。
- 结算在用户行锁内读取数据库策略；不使用进程全局缓存作为账务真相。新请求立即用新配置，已冻结任务遵守冻结分账上限，按原来源释放。
- 非法/过期/重放页面令牌及蜜罐请求不发签到奖励；安全事件与三天观察清退规则独立，不凭单个弱信号直接处罚。

## 架构选择
使用现有 settings 单条 JSON 策略，无 DDL。消费事务直接读取配置；避免本地 atomic 策略造成跨实例差异。钱包纯函数提供显式策略参数和兼容默认值。冻结字段已有分项金额，可据此限定后续消费，策略快照保存于已有 image_hold 流水 notes，兼容旧冻结默认 2:1；不新增表字段。风险：配置改变可用额度，缓存须同步；已冻结不得受新比例影响。代码回滚前需将比例恢复默认，已产生流水不可删账。
