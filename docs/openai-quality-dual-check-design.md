# OpenAI 糖果与鹈鹕双重检测

2026-10-28。本地分支 `feature/openai-quality-dual-check`，基于 `v0.2.18.4`。

## 已确认的需求

- 同一账号、同一模型及协议/传输/effort/tier，执行糖果题与鹈鹕动画生成两项测试。
- 鹈鹕采用自动视觉评审；两项均通过才算通过，明确失败参与原有降权/隔离，恢复也必须双通过。评审不确定、请求失败不冒充降智。
- 保留普通 OpenAI 分组检测能力；只有原本支持控制的不降智来源组可控制调度。一个账号的两个模型仍是独立策略。
- 监控页参考 manxue.ai：统计、最近60次色块、鹈鹕作品墙、糖果卡片、可点击详情；保留完整记录、筛选与账号策略管理。
- 新增视觉评审账号/来源组/模型配置；未配置或渲染器不可用时明确显示待评审/不可用，不假判通过。
- 只实施本地代码与隔离测试，不启用生产检测，不调用真实付费账号，不部署、提交、合并或推送。

## 检测与证据

旧 `candy/1/strict-json-v1` 保持兼容。新增 `dual/1/dual-visual-v1`；创建时选择检测套件，旧策略不自动升级。升级使用现有替换策略机制，历史保留，新证据重新累积。benchmark 已参与 `ScopeHash`，不改变实际调度匹配的 `ControlScopeHash`。

一个双检测任务依次执行糖果请求、鹈鹕请求、四帧截图、视觉评审请求。独立生成避免两次请求串扰；每阶段释放账号并发位，允许评审与被测账号相同而不死锁。总超时覆盖整个任务，可取消，无自动付费重试。

糖果沿用严格 JSON 评分（唯一 answer 整数，正确值21）。鹈鹕适配仓库 `third_party/manxue-ai` 的固定 SVG 动画提示词、结构校验、四帧评审方法，保留 Apache-2.0 来源，不修改 upstream 快照。视觉标准为鹈鹕、完整自行车、骑乘姿态、协调运动；严格接收四项布尔值或 null，任意 false 为未通过，null 为不确定，全部 true 才通过。生成 SVG 的结构校验只能判安全与可预览，不能证明画得正确。

双通过为 passed；任一明确答错/结构未达要求/视觉标准 false 为 incorrect；否则因不可用、截断、超时或不确定为 unknown/error。unknown/error 不增加失败或恢复证据。保留各项原因及资源用量，用户可从详情确认。

评审配置随任务快照固定；更换评审配置时建立新的全局控制代次，旧任务不能更新新代次状态。发送前重查被测/评审账号的路由和可用性，凭证只在传输层读取，不存入快照或结果。

## 持久化与预算（无新增 DDL）

复用 `account_quality_test_runs.result` JSONB 保存分项元数据和持久发送意图，复用受保留期控制的 `response_text` 保存带版本的正文包（糖果、SVG、评审原文）。新记录的正文包只在详情或限量作品接口读取；列表不返回原文。正文到期后作品和原文均不可获取，元数据继续保留；旧记录仍按普通文本读取。

预算按实际请求逐次扣计。claim 预留首个调用；后续阶段在发送事务内核验租约/配置代次/取消/阶段唯一性，并分别申请与扣除一次全局及策略日额度。每阶段的发送意图在请求前持久化；崩溃后任务只中断，不重放。跨日按发送当日记账，失败未发送的阶段不扣；已提交发送意图的网络失败保守计一次。容量预览按双检测至多3次计算，界面清楚区分任务数与模型调用数。

阶段结果聚合字段为兼容性新增，现有状态/策略/记录路径保留。原始输出每段有字节上限，正文包不能用字节截断破坏 JSON。

## 渲染与评审部署

新增可选的私网渲染服务，基于 Playwright Chromium，将安全 SVG 截取4个时间点。Go 后端只发送 SVG，不发送 API Key。渲染器地址由运维环境变量指定，管理员页面不接受任意 URL/命令。服务限制请求体、并发、单任务时间及返回大小，Chromium 禁止网络、脚本、下载、外部资源；不渲染任意 HTML。提供独立 Docker/Compose 示例和健康检查；未部署时糖果单检可继续使用。

浏览器作品使用图像上下文显示已校验 SVG，不使用 `v-html` 或允许脚本的 iframe。预览只能来自后端保留期内的作品接口；作品失败、过期、未生成均有独立空态。作品列表限量分页，取消/离页时丢弃过期响应并释放 blob URL。

## 展示设计

风格参照用户截图，适配现有后台浅色/深色。布局实验度3、动效2、信息密度8：主区域用于作品与判定，管理操作收在“账号策略”视图。中性底色，绿色通过、红色未通过、琥珀色不确定、灰色请求失败；状态同时有文字，色块支持键盘及可读名称。

- 页头保留“检测记录 / 配置 / 刷新”。
- 结果视图显示当前筛选范围保留期内最近60次的通过/未通过/未判定及有效判定通过率；请求异常不进入分母。账号策略视图保留原24小时聚合。
- 最近60次按检测时间排列，可点击打开对应任务，标明当前筛选范围和新旧方向；不与24小时汇总混称。
- 左侧鹈鹕作品网格：动画缩略图、斜角状态、账号/分组名、模型、时间、耗时及Token；失败卡也保留原因，避免作品墙只展示成功请求。
- 右侧糖果卡片：答题结果、21期望值、账号/模型、时间、输入/输出/推理Token和费用；未知数据展示“—”。
- 详情按“糖果 / 鹈鹕 / 视觉评审”切换，显示原文、动画、四项评审标准、阶段指标、整体结果、是否计入策略状态和完整条件快照。
- 所有普通分组显示真实名称；作品和记录筛选必须服务端执行，不能用当前一页代替全量结果。

## 影响面与验证出口

已核对真实入口：`accountquality/{types,runner,repository,service,http,preview,prepared}.go`、`service/account_quality_provider.go`，前端三页及共享详情组件、API类型与双语包。使用 rg 复核引用，仓库未发现可用 Chromium Go 封装，故不引入 Go 浏览器依赖。

1. 核心模型/评分/正文：单测覆盖双结果真值表、严格评审 JSON、恶意SVG/资源/CSS、旧记录兼容、过期正文与不泄露列表。
2. 预算/状态：隔离 PostgreSQL 验证三次扣计、重复阶段拒绝、跨日、预算不足、取消/租约失效、评审切换新代次，旧 candy 回归。
3. 上游传输：本地 HTTP/SSE/WS 桩检验两份提示词及视觉内容、usage、失败阶段；不调用真实账号。
4. 渲染器：隔离样例真实截图4帧，网络阻止与请求大小/超时/异常验证，任何失败不生成 passed。
5. 前端：组件交互、完整中文/英文、vue-tsc、ESLint、生产构建；真实浏览器使用模拟API验证作品、色块、详情、筛选、错误/空态、离页及窄屏，并保存截图。
6. 分阶段追加 `.ai-memory/handoff.md`；失败回到相应阶段，不重复付费调用，不隐藏未验证项。

回退：暂停自动任务并等待运行结束，停用双检测策略后回退应用，保留数据库/历史及旧tag。无生产DDL、数据重写或旧策略批量升级。渲染器是可选依赖，不能把未部署视为测试通过。

## 糖果详解 v2 与判定状态补充

- 为避免改变既有证据含义，保留 candy/1/strict-json-v1 与 dual/1/dual-visual-v1，新增 candy/2/answer-explanation-v2、dual/2/dual-visual-v2。版本进入既有 ScopeHash；没有 DDL 或自动迁移。新建默认v2，旧策略经预览手动升级，保留检测套件、账号、模型、开关及历史，重新积累证据。归档替换不继承旧隔离状态，确认文案明确提示此影响。
- 新糖果格式恰好包含整数answer和非空字符串explanation，拒绝重复键、额外字段、数值转换、尾随正文及未完成响应。说明是模型面向读者的解答，不是内部推理，不对说明正确性另行评分。旧版提示词和整数判分保持兼容。
- 题目与实际提示词由详情接口提供；explanation仅在原文未过期且明确请求正文后解析，不写入永久结果元数据。Markdown复用marked/DOMPurify，白名单标签及空属性集，禁链接、图片和嵌入资源。
- 作品墙与详情共用状态映射：未评审、检测异常、评审不确定、通过/未通过；视觉原判分规则不变。详情列四项具体标准，配置入口直达全局设置，未评审时四项不伪装成已评审。
- 本轮验证：accountquality全包race99（含新格式/版本/保留期及HTTP入口6种正文访问场景）；service定向race通过，两协议各覆盖v1/v2及未配置评审的两次调用；前端28、i18n、ESLint、类型和生产构建通过。普通后端及含前端embed构建通过。浏览器在本地组件验收页验证题目、详解标题/列表/表格、旧版与过期空态、未评审与不确定四项结果及深色可读性，截图为示例数据。
