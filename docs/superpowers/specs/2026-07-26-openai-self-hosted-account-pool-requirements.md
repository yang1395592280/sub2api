# OpenAI 自建号池分组需求规格

日期：2026-07-26
状态：已确认并完成开发，待部署环境验收
范围：OpenAI 固定分组与自动最优惠分组的账号调度

关联文档：

- [OpenAI 自动最优惠分组质量优先与首字切换开发方案](./2026-07-21-openai-auto-cheapest-quality-first-failover.md)
- [OpenAI 统一调度与控制台优化设计](./2026-07-13-openai-unified-scheduler-design.md)

## 1. 需求结论

系统新增一种 OpenAI 管理端分组角色：**自建号池分组**。它仅是可调度账号的容器，不是用户购买、API Key 绑定或计费用的业务分组。

每个普通 OpenAI 分组可选择关联一个自建号池，且**多个普通分组可以同时关联同一个号池**，例如 `0.15 -> P` 和 `0.20 -> P` 可以同时存在。当固定分组 API Key 或自动最优惠逻辑选中该普通分组时，选号分两个阶段：

1. 先从该分组关联且已启用的自建号池选择可用账号。
2. 只有号池在本次请求下已无可用账号，才从当前普通分组自身选号。

无论账号来自号池还是普通分组本身，用户权限、分组配置、计费倍率、用量归属和自动最优惠价格层级均以**有效分组**为准。号池不改变价格，只改变候选账号的优先级。

## 2. 背景与目标

当前 OpenAI 固定分组以本组账号为选号范围；自动最优惠则先按有效倍率、`sort_order`、分组 ID 对普通分组排序，再逐组选号。

新需求需要多个 OpenAI 业务分组共享一组管理员自建账号，并在不改变用户价格层级的前提下优先使用这些账号。

功能目标：

1. 管理员可创建、编辑、启用和关闭 OpenAI 自建号池。
2. 可维护号池中的 OpenAI 账号及组内优先级。
3. 普通 OpenAI 分组可不关联号池，或关联一个号池。
4. 同一号池可被多个普通 OpenAI 分组关联。
5. 固定分组和自动最优惠都遵守“先号池、后本组”。
6. 号池账号承接请求时，仍按有效分组的倍率和权限执行。
7. 号池关闭后立即退出后续选号，但不中断已开始的上游请求。
8. 调度审计能同时说明有效分组和账号来源分组。

## 3. 非目标

- 不改变 OpenAI 计费公式、账号倍率、渠道结算或峰值倍率语义。
- 不将号池做成可售卖订阅、可兑换套餐或可直接绑定 API Key 的分组。
- 不将号池作为自动最优惠的独立价格层级。
- 不改变现有健康评分、熔断、并发槽、排队和失败分类算法。
- 不扩展到 Anthropic、Gemini、Grok、Antigravity 或 Composite 分组。
- 首期不支持一个普通分组同时绑定多个号池。

## 4. 术语与责任

| 术语 | 定义 |
| --- | --- |
| 普通 OpenAI 分组 | 现有面向用户和 API Key 的 OpenAI 分组，具有倍率、权限、限额和调度配置。 |
| 自建号池分组 | 管理端账号容器，只提供候选账号，不提供计费或用户权限语义。 |
| 有效分组 | 固定 API Key 选中的分组，或自动最优惠当前扫描到的价格分组。 |
| 账号来源分组 | 本次选中账号所属的候选容器，可以是号池，也可以是有效分组本身。 |
| 号池阶段 | 在有效分组的业务上下文中，从其关联号池选号的第一阶段。 |
| 本组阶段 | 号池阶段无可用账号后，从有效分组本身选号的第二阶段。 |
| 价格层级 | 自动最优惠按有效倍率排序后的某个普通 OpenAI 分组。 |

## 5. 分组和关联规则

### 5.1 概念模型

OpenAI 分组在业务上分为：

- `standard`：普通 OpenAI 业务分组。
- `self_hosted_pool`：自建号池分组。

上述为需求层概念，实际字段名和存储方式由技术设计确定。

### 5.2 关联基数与校验

- 一个普通 OpenAI 分组可关联 `0..1` 个号池。
- 一个号池可被 `0..N` 个普通 OpenAI 分组关联。
- 关联的唯一性只限制普通分组这一侧；不得对号池一侧设置唯一约束，不得因号池已被其他分组关联而拒绝新关联。
- 号池不能关联自身或另一个号池。
- 非 OpenAI 分组不能创建或绑定 OpenAI 号池。
- 号池只允许加入 `platform=openai` 的账号。
- 同一 OpenAI 账号可同时属于号池和普通分组。
- 同一次请求内必须按物理账号 ID 去重，不得因切换来源分组而立即重试已失败账号。
- 号池的账号成员关系及组内 `priority` 复用现有分组成员能力。

### 5.3 号池不具有的业务语义

号池虽使用“分组”作为容器，但以下属性对用户请求不生效：

- 号池自身的普通倍率、峰值倍率和用户专属倍率。
- 号池的订阅类型、用户成员、限额和 RPM 配置。
- 号池自身的“允许自动最优惠”开关。
- 号池作为 API Key 直接分组、订阅权益或兑换码目标的能力。

管理端应隐藏、禁用或明确标识这些无效配置，避免引起计费误解。

## 6. 调度不变量

1. 先确定有效分组，再确定账号来源分组。
2. 号池只增加优先候选账号，不把有效分组替换为号池。
3. 号池阶段和本组阶段都复用现有 OpenAI 选号器，不建第二套健康、负载或熔断逻辑。
4. 账号状态、`schedulable`、模型兼容、endpoint/transport 能力、Compact、图片能力、配额、运行时封禁、健康熔断、并发容量和价格保护仍是不可绕过的过滤。
5. `previous_response_id` 等强亲和保持现有上下文一致性；号池优先仅用于新选择或允许迁移的场景。
6. 单账号失败只排除该账号，应先尝试当前来源分组的其他账号；当前来源分组确认无可用账号后才进入下一阶段。
7. 已向客户端输出语义内容后，不得通过号池或分组切换拼接第二个上游响应。

### 6.1 号池耗尽判定

当前请求经过现有调度器后，满足以下任一条件，可进入本组阶段：

- 所有号池账号均被硬过滤排除。
- 所有符合基础能力的账号均已在当前请求失败并进入排除集。
- 经过现有并发槽和等待策略后，调度器明确返回无可执行候选。
- 号池已关闭、不存在、被软删除或关联已失效。

不得仅因某一个号池账号单次失败，就直接跳到本组阶段。

### 6.2 号池选号上下文

- 候选账号来自号池成员关系。
- 自动调度是否影响真实选号，由有效分组的开关和全局运行模式决定。
- 模型映射、推理强度上限、endpoint 权限、价格保护和分组级规则以有效分组为准。
- 账号能力、账号级模型映射、上游价格、账号倍率、并发和健康以物理账号为准。
- 号池的成员 `priority` 用于号池阶段；有效分组的成员 `priority` 仅用于本组阶段。

## 7. 固定分组调度

假设 API Key 固定绑定普通 OpenAI 分组 `G`，`G` 关联号池 `P`：

```text
请求进入 G
  -> P 存在且 active？
     -> 否：直接从 G 选号
     -> 是：从 P 选号，但使用 G 的业务与计费上下文
        -> P 选号成功：转发请求
        -> P 耗尽：从 G 选号
           -> G 选号成功：转发请求
           -> G 耗尽：按现有逻辑返回无可用账号
```

`G` 未关联号池，或 `P` 已关闭时，行为与当前固定分组完全一致。

## 8. 自动最优惠调度

### 8.1 分组排序不变

号池不进入自动最优惠的候选分组列表。普通 OpenAI 候选分组仍按现有顺序排列：

1. 用户专属分组倍率，没有时使用分组默认倍率，升序。
2. `sort_order` 升序。
3. 分组 ID 升序。

号池优先只在每个已排好的价格分组内部生效。

### 8.2 两级扫描次序

```text
for G in 普通 OpenAI 候选分组（有效倍率从低到高）:
    if G 关联的号池 P 已启用:
        按 G 的业务上下文尝试 P 中账号
        if 成功:
            按 G 归属和计费，结束

    尝试 G 自身账号
    if 成功:
        按 G 归属和计费，结束

所有 G 均耗尽:
    按现有逻辑返回无可用账号
```

### 8.3 0.10 / 0.15 / 0.20 示例

| 分组 | 有效倍率 | 关联号池 |
| --- | ---: | --- |
| A | 0.10 | 无 |
| B | 0.15 | P |
| C | 0.20 | P |

完整调度顺序：

```text
A 本组账号
  -> A 耗尽
P 号池账号（有效分组 = B，倍率 = 0.15）
  -> P 在 B 上下文中耗尽
B 本组账号（倍率 = 0.15）
  -> B 耗尽
P 号池账号（有效分组 = C，倍率 = 0.20）
  -> P 在 C 上下文中耗尽
C 本组账号（倍率 = 0.20）
  -> C 耗尽
返回无可用账号
```

在 B 阶段已明确失败的物理账号，进入 C 阶段再次扫描 P 时仍必须被排除。但系统仍应逻辑上进入 C 的号池阶段，因为 C 的分组规则、模型映射或价格保护可能使候选结果与 B 不同。

### 8.4 与现有质量分层的组合

自动最优惠已存在“质量选择 + 可用性兜底”语义。新功能在每个价格分组内，对号池阶段和本组阶段分别执行现有选择规则。

必须保留：

- 低价组内存在达标账号时，不得跳到更高价格组。
- 单账号失败不等于整个来源分组耗尽。
- 首字超时后的严格质量重选不得因号池而恢复低置信兜底。
- 已失败账号排除、分组短熔断和最大倍率限制仍有效。

## 9. 号池启停和删除

### 9.1 关闭

号池变为 `inactive` 后：

- 新的固定分组和自动最优惠选号均跳过该号池。
- 普通分组与号池的关联保留，不自动解除。
- 普通分组继续使用自身账号，不因号池关闭而停用。
- 账号如果还直接属于普通分组，仍可通过该普通分组被调度。
- 已获取账号并开始转发的请求不强制中断；关闭对下一次选号生效。

### 9.2 重新启用

- 所有保留关联的普通分组自动恢复号池优先。
- 账号仍需通过状态、健康、能力、配额和并发过滤。
- 重新启用不清除账号级熔断或运行时封禁。

### 9.3 删除

被普通分组引用的号池默认禁止删除。管理员需先解除所有关联，避免隐式改变多个业务分组的选号行为。

## 10. 计费、限额与归属

### 10.1 倍率

```text
用户有效分组倍率
  = 用户在有效分组上的专属倍率（如有）
  else 有效分组默认倍率

最终账号倍率
  = 实际被选中的物理账号倍率
```

号池的默认倍率、用户专属倍率和峰值倍率不参与计费。

- B 倍率为 `0.15`，账号来自号池 P，仍按 B 的 `0.15` 计算分组倍率。
- C 倍率为 `0.20`，账号仍来自 P，则按 C 的 `0.20` 计算。
- 用户在 B 有专属倍率 `0.12`，则 P 账号承接 B 请求时按 `0.12` 作为用户有效分组倍率。

### 10.2 以有效分组为准

- 用户权限、订阅限额、日/周/月限额。
- 分组 RPM 和用户专属 RPM。
- 自动最优惠最大倍率限制。
- 模型映射、推理强度上限、endpoint 能力和分组级价格保护。
- 正常用量 `group_id`、费用归属、用户分组统计和 API Key 最后有效分组。

### 10.3 以物理账号为准

- 账号状态、可调度状态和临时暂停。
- 账号配额、并发上限、上游健康和熔断。
- 账号级模型映射、能力、上游渠道价格和账号倍率。

### 10.4 审计归属

普通用量和费用必须记录有效分组 ID，不得改记为号池 ID。管理端调度审计还需表达：

- `effective_group_id`：有效分组 ID。
- `account_source_group_id`：账号来源分组 ID。
- `account_source_type`：`self_hosted_pool` 或 `effective_group`。
- `pool_group_id`：号池 ID，非号池选号时为空。
- `pool_fallback_reason`：从号池进入本组阶段的原因。

是否在 `usage_logs` 增加字段，或仅写调度决策审计，由技术设计根据查询和存储成本决定；但语义必须可追溯。

## 11. 管理端需求

### 11.1 分组列表

- 明确区分“OpenAI 普通分组”和“OpenAI 自建号池”。
- 号池显示状态、账号数、可用账号数和被关联分组数。
- 普通 OpenAI 分组显示已关联号池名称，或“未关联”。
- 号池不显示用户售卖倍率，或明确标记“不参与计费”。

### 11.2 创建和编辑号池

提供名称、描述、状态、初始账号成员和成员优先级。平台固定为 OpenAI，分组角色固定为自建号池。

不提供或不允许生效：订阅类型、用户成员、限额、兑换码、用户计费倍率、峰值倍率、用户专属倍率、允许自动最优惠直接选择、关联其他号池。

### 11.3 普通 OpenAI 分组编辑

增加“优先自建号池”配置：

- 默认为“不关联”，保持存量行为。
- 只展示 OpenAI 自建号池选项。
- 某个号池已被其他普通分组选中后，仍必须保留在当前分组的可选列表中。
- 选项显示号池状态和可用/总账号数。
- 允许绑定已关闭号池，但必须提示“当前不会参与调度”，便于预先配置。
- 更换或解除关联只影响后续选号，不修改历史用量。

### 11.4 启停操作

- 关闭前显示受影响的普通 OpenAI 分组数量和名称。
- 关闭需二次确认，明确“关联分组将直接使用自身账号”。
- 启用时提示“所有保留关联的分组将恢复优先使用此号池”。

## 12. 接口与数据契约

本节只定义业务契约，不锁定具体 URL 和存储结构。

管理端分组数据需能表达：

- 分组角色。
- 普通分组关联的号池 ID、名称和状态。
- 号池的引用分组数、账号数和可用账号数。

服务端必须拒绝：

- 非 OpenAI 分组设置为号池。
- 普通分组关联非 OpenAI 号池、普通分组或自身。
- 号池再关联号池。
- API Key、订阅、兑换码或用户允许分组直接指向号池。
- 向号池加入非 OpenAI 账号。

用户侧可选分组列表、支付套餐和 API Key 分组选择器必须排除号池。未传入新字段的旧请求默认创建普通分组；更新时不得意外清空已有号池关联。

号池状态、关联和成员变更应按现有缓存失效机制传播，不得让已关闭号池长时间承接新请求。

## 13. 适用请求路径

号池优先必须接入所有使用统一 OpenAI 账号选择的路径，包括：

- Responses HTTP/SSE 和 Responses WebSocket。
- Chat Completions 原生与 Responses 转换路径。
- OpenAI Messages 兼容路径。
- Embeddings。
- Images generations/edits。
- OpenAI Live。
- Messages Count Tokens 与 Alpha Search。
- 其他已复用统一 OpenAI 选号器的路径。

各路径仍执行自身 endpoint、transport、模型、图片和 Compact 能力检查。开发时需盘点仍使用独立选号的 OpenAI 入口，防止部分路径绕过号池。

## 14. 异常和边界场景

| 场景 | 期望行为 |
| --- | --- |
| 普通分组未关联号池 | 完全沿用现有选号逻辑。 |
| 关联号池已关闭 | 跳过号池，直接调度普通分组。 |
| 号池为空 | 直接进入本组阶段。 |
| 号池部分账号不支持模型 | 过滤不支持账号，继续尝试号池其他账号。 |
| 号池某账号返回可切换故障 | 排除该账号，按现有故障分类和重试规则尝试号池其他账号。 |
| 号池全部账号熔断或封禁 | 进入本组阶段。 |
| 号池和本组有重复账号 | 按物理账号 ID 去重，不立即重试已失败账号。 |
| 号池在请求中途关闭 | 已开始上游请求不中断；发生重选时不再从号池取新账号。 |
| 关联指向已删除号池 | 按未关联处理并记录异常审计，不将数据异常转为用户 `502`。 |
| 读取号池关联或成员失败 | 降级到有效分组自身，并记录结构化告警。 |
| 有效分组本身关闭 | 按现有分组不可用处理，不能通过号池绕过。 |
| 自动最优惠倍率上限为 0.15 | 可使用 A(0.10) 和 B(0.15) 的号池/本组阶段，不得进入 C(0.20) 或以 C 语义使用号池。 |

## 15. 可观测性

调度决策至少记录：

- API Key ID、用户 ID、请求模型、endpoint 和 transport。
- 有效分组 ID、有效倍率。
- 号池 ID、号池状态。
- 账号来源类型、账号来源分组 ID、最终账号 ID。
- 是否从号池进入本组，以及原因。
- 自动最优惠的价格组升档次数。

建议指标：号池命中率、关闭跳过次数、号池到本组的降级次数及原因、按有效分组统计的号池承接比例、号池账号错误率/首字延迟/并发槽获取率、号池降级后最终成功率。

日志不得输出账号 Token、Cookie 或其他敏感凭证。

## 16. 兼容、灰度与回滚

### 16.1 存量兼容

- 所有存量分组默认为普通分组。
- 所有存量普通分组默认不关联号池。
- 功能不配置时，固定分组、自动最优惠、计费和用量行为必须与现网一致。
- 旧版管理端更新分组时，不得因未传新字段而清空号池关联。

### 16.2 灰度顺序

1. 仅上线数据与管理配置，运行时号池调度保持关闭。
2. 对一个低风险固定 OpenAI 分组开启，验证倍率和用量归属。
3. 对一个自动最优惠候选分组开启，验证价格顺序和跨组切换。
4. 观察号池命中率、错误率、首字延迟、最终成功率和倍率归属后逐步扩大。

### 16.3 回滚

- 首选运行时回滚方式是关闭号池或解除关联。
- 回滚后普通分组继续使用自身账号，不要求回退数据库迁移。
- 历史用量、调度日志和关联数据保留，便于追溯和重新启用。

## 17. 验收标准

### 17.1 固定分组

1. G 未关联号池时，行为与现网一致。
2. G 关联已启用号池 P，P 有可用账号时，不得选中 G 自身账号。
3. P 耗尽时，必须自动选择 G 的可用账号。
4. P 和 G 均耗尽时，返回现有无可用账号错误，不 panic。
5. P 关闭时，直接使用 G 账号，不请求 P 账号并发槽。

### 17.2 自动最优惠

1. A(0.10) 有可用账号时，不得因 B(0.15) 关联号池而跳过 A。
2. A 耗尽且 B 关联 P 时，必须先调度 P，再调度 B。
3. P 在 B 上下文中成功时，有效分组和计费倍率仍为 B/0.15。
4. P 与 B 均耗尽后进入 C(0.20)；C 关联 P 时仍先进入 P 阶段，但不重试当前请求已失败账号。
5. P 在 C 上下文中成功时，有效分组和计费倍率为 C/0.20。
6. API Key 最大倍率上限不得被号池绕过。
7. 首字严格重选、分组短熔断和已失败账号排除保持有效。

### 17.3 计费和数据

1. P 账号承接 B 请求时，分组倍率快照、usage `group_id`、RPM 和订阅限额均使用 B。
2. 物理账号倍率仍来自实际账号。
3. 管理员可通过审计数据区分“B 本组账号”和“P 号池账号”。
4. 普通用户的用量展示不暴露号池内部账号或管理结构。

### 17.4 管理端和校验

1. 可创建、关闭和重新启用 OpenAI 号池。
2. 一个普通 OpenAI 分组最多关联一个号池，一个号池可被多组关联。
3. B(0.15) 和 C(0.20) 可以同时保存对同一号池 P 的关联，且解除 B 的关联不得影响 C 与 P 的关联。
4. P 已被 B 关联后，编辑 C 时 P 仍在号池下拉选项中且可成功选中。
5. 用户侧、API Key、支付套餐、订阅和兑换码选择器不出现号池。
6. 服务端拒绝跨平台关联、自关联、号池嵌套和非 OpenAI 账号入池。
7. 关闭号池时明确显示影响范围，且保留关联。

## 19. 开发前待确认事项

以下事项不影响主流程理解，但会影响最终数据模型和界面形态。本文档先给出建议默认值，开发前应确认。

| 待确认项 | 建议默认 | 影响 |
| --- | --- | --- |
| 系统只允许一个全局号池，还是允许多个 | 允许多个；每个普通分组最多绑定一个 | 决定全局配置还是分组自关联 |
| 号池账号全部并发已满时，等待还是立即进入本组 | 复用现有并发槽和等待策略，明确无候选后再进入本组 | 影响首字延迟和号池命中率 |
| 关闭号池是否强制中断已执行请求 | 不中断，仅对下一次选号生效 | 影响长连接和流式一致性 |
| 被引用号池的删除策略 | 有引用时拒绝删除，先手工解除关联 | 影响管理交互和数据完整性 |
| 普通用户的用量页是否显示“号池承接” | 不显示，仅管理员审计可见 | 影响用户界面和内部信息暴露 |
