# OpenAI 自动调度 UI 设计规格

日期：2026-06-28

## 目标

将 OpenAI 自动调度后台页面调整为更适合运维排障的管理界面。主页面采用“方案 A：运维表格版”，并吸收“方案 B：列表 + 详情抽屉”的单渠道深度排障能力。

本阶段只定义 UI 和交互设计。实现时应在现有 `frontend/src/views/admin/OpenAIAutoSchedulerView.vue` 基础上改造，不改变后端调度算法语义。

## 设计稿

静态设计稿文件：

- `outputs/openai-auto-scheduler-ui-options.html`

最终采纳：

- 主页面：方案 A，左侧分组调度开关 + 右侧高密度渠道表格。
- 详情能力：吸收方案 B，点击渠道后打开详情抽屉，展示评分拆解、事件和完整错误。
- 方案 C 暂不作为本次主流程实现，可作为后续异常看板增强。

## 页面结构

### 顶部状态区

顶部展示全局自动调度关键状态：

- 全局自动调度：启用 / 关闭。
- 当前分组：默认选中分组管理排序后的第一个分组。
- 检测模型：默认 `gpt-5.4`，可切换 `gpt-5.5`。
- 探测策略：探测间隔、慢响应阈值。
- 成本权重：展示为百分比。

全局开关关闭时，页面需要明确提示“关闭后走系统原调度”。分组开关关闭时，当前分组仍可查看探测分数，但不参与 OpenAI 自动调度。

### 左侧分组区

左侧展示 OpenAI 分组列表，并突出“分组是否参与自动调度”：

- 默认选中排序后的第一个分组。
- 每个分组展示：分组名称、渠道数量、默认检测模型、调度开关。
- 当前选中分组用浅色背景和边框高亮。
- 开关关闭时，需要在当前分组说明中显示“不参与自动调度”。

切换分组后：

- 右侧渠道表格同步刷新为该分组数据。
- 模型筛选默认使用该分组配置的检测模型；没有配置时使用 `gpt-5.4`。

### 右侧渠道表格

表格用于快速比较同组渠道质量。列定义如下：

1. 上游渠道
   - 展示渠道名称，优先使用上游渠道名。
   - 次要信息展示 base URL、标签或价格。
2. 状态
   - 展示 `running`、`observing`、`open`、`half_open`。
   - 状态需要配色：健康、观察、熔断、恢复中。
3. 实际调度分
   - 展示最终用于排序的分数。
   - 文案明确为“实际调度分 = 健康分 + 价格修正”。
   - 如果熔断冷却未结束，需要提示“冷却未结束前不进入候选”。
4. 健康分拆解
   - 展示基础分、延迟修正、错误惩罚、恢复加分、成本修正。
   - `base 0.6000` 改为 `基础分 0.6000（新渠道默认起点）`。
5. 探测样本
   - 展示请求样本、TTFB 样本、最近延迟、最近 TTFB、最近 HTTP 状态。
6. 最近风险
   - 正常渠道显示“无异常”。
   - 慢响应显示“连续慢响应 2/3”等可读摘要。
   - 错误显示短摘要，如“超时：context deadline exceeded”。
   - 完整错误进入详情抽屉，不在表格中横向铺开。
7. 操作
   - 手动探测。
   - 重置分数。
   - 查看详情。

表格需要支持横向信息密度，但不能让长错误文案撑破布局。长渠道 URL 和错误内容都应省略显示，并可通过详情查看完整内容。

## 详情抽屉

点击渠道行或“查看详情”打开右侧抽屉。抽屉展示当前渠道的深度信息：

- 渠道名称、base URL、标签、价格、检测模型。
- 当前状态和冷却信息。
- 实际调度分：
  - 健康分。
  - 价格修正。
  - 实际调度分。
  - 是否因为熔断冷却被跳过。
- 评分拆解：
  - 基础分。
  - 延迟修正。
  - 错误惩罚。
  - 恢复加分。
  - 成本修正。
- 样本数据：
  - 请求样本。
  - TTFB 样本。
  - 慢响应率。
  - 错误率。
  - 卡住率。
  - 连续慢响应、连续错误、连续成功。
- 最近事件：
  - 探测成功。
  - 探测失败。
  - 慢响应。
  - 错误。
  - 熔断。
  - 半开恢复。
- 完整错误：
  - 表格中只显示错误摘要。
  - 抽屉中展示完整错误，保留可复制能力。

## 调度说明文案

页面需要避免用户误解“只看健康分”。建议在顶部或详情中固定展示以下说明：

自动调度生效条件：

1. 全局自动调度开启。
2. 当前分组自动调度开启。
3. 账号仍通过系统原候选过滤。
4. 熔断状态未处于不可用冷却期。

排序规则：

1. 状态优先级：`half_open` > `running` > `observing` > `open`。
2. `open` 且冷却未结束的渠道跳过。
3. 同一状态内按实际调度分排序。
4. 实际调度分 = 健康分 + 价格修正。
5. 同分时使用账号优先级、最近使用时间和原始顺序兜底。

## 配置编辑

“编辑调度配置”应保持可用，并以分组和全局配置分层展示：

- 全局配置：
  - 全局开关。
  - 探测间隔。
  - 慢响应阈值。
  - 重慢阈值。
  - 连续慢响应熔断阈值。
  - 连续错误熔断阈值。
  - 熔断冷却。
  - 半开成功阈值。
  - 恢复步长。
  - 成本权重。
- 分组配置：
  - 当前分组是否参与调度。
  - 当前分组默认检测模型，默认 `gpt-5.4`。

如果当前后端暂未提供分组默认检测模型字段，实现时需要在 UI 层先沿用筛选模型默认值；后端字段是否补充应在实现计划中单独确认。

## 响应式规则

桌面端：

- 左侧分组区固定宽度约 280-320px。
- 右侧表格占满剩余空间。
- 详情抽屉从右侧打开，宽度约 360-440px。

窄屏：

- 左侧分组区移动到表格上方。
- 表格保留横向滚动。
- 详情抽屉改为全宽覆盖层或页面内展开。

## 视觉规则

- 页面风格保持后台运维工具，不做营销式布局。
- 信息密度高但层级清楚。
- 状态颜色固定：
  - running：绿色。
  - observing：黄色。
  - open：红色。
  - half_open：蓝 / 紫色。
- 卡片圆角不超过 8px。
- 长文本必须截断，详情中再完整展示。
- 标注文案要业务化，避免只展示 `base`、`latency`、`ttfb` 这类短英文。

## 测试与验收

实现后至少验证：

1. 默认分组选中排序后的第一个分组。
2. 当前分组开关可以控制该分组是否参与调度。
3. 模型默认 `gpt-5.4`，可切换 `gpt-5.5`。
4. 表格中展示上游渠道名，而不是账号兜底名。
5. `基础分 0.6000` 有清楚解释。
6. 错误长文案不会撑破表格。
7. 详情抽屉能展示完整错误、评分拆解和探测样本。
8. 编辑调度配置入口可用。
9. 全局关闭时文案明确说明回退系统原调度。
10. 分组关闭时文案明确说明该分组不参与自动调度。

前端验证建议：

- 运行现有 OpenAI 自动调度页面单测。
- 启动前端页面手动检查桌面宽度。
- 检查窄屏下没有文本重叠和按钮溢出。

## 非目标

本次 UI 设计不改变以下内容：

- 后端调度算法。
- 分数计算逻辑。
- 熔断状态机。
- 现有 OpenAI 账号选择入口。
- 方案 C 异常看板的独立页面实现。

## 自检结果

- 无未决项。
- 主页面方案、详情抽屉方案和非目标范围一致。
- 已明确健康分与实际调度分的关系。
- 已明确全局开关和分组开关的生效关系。
- 已明确默认分组、默认模型和错误展示方式。
