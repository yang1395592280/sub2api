# OpenAI 质量检测与检测记录

## 页面入口

管理员侧栏的一级“质量监控”菜单下提供三个入口。模块总开关在“系统设置 → 二改功能”，关闭后停用旧检测和调度干预，历史保留。独立的分组定时 HTML 鹈鹕测试及账号作品档案见 [分组定时鹈鹕测试](group-pelican-tests.md)。

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| OpenAI 质量监控 | `/admin/openai-quality` | 默认展示最近60次检测色块、鹈鹕作品墙和糖果结果；账号策略标签保留质量控制、手动检测及24小时时间线 |
| 检测记录 | `/admin/openai-quality/records` | 按时间查看历史执行、结果、耗时及原始回答 |
| 质量检测配置 | `/admin/openai-quality/settings` | 创建策略、编辑已有规则、设置全局开关和预算 |

监控页顶部可进入全部检测记录；账号的“执行历史”按账号及来源分组筛选；模型时间线内的历史入口按策略筛选，保留该策略旧检测条件下的记录。

## 创建与执行

1. 在“质量检测配置 → 创建检测策略”选择来源分组，再选择组内账号。支持所有启用的 OpenAI 业务分组，包括普通 0.1 倍率、降智组；内部账号池通过业务来源组选择。
2. 填写一个或两个模型。同一账号的两个模型生成独立策略，分别记录结果；每批最多 100 条策略，两个模型时最多选择 50 个账号。
3. 设置检测周期、单日调用预算；协议、传输、推理强度和高级规则按需展开。检测方式默认“糖果 + 鹈鹕”，也可选择糖果单检；双检测须先配置视觉评审和私网渲染器。
4. 先“预览影响”，再“保存策略”或“保存并检测”。修改选择或参数后需要重新预览。
5. 需要定时执行时，同时启用策略的“自动检测”和“全局设置”中的自动检测开关。

保存并检测、立即检测以及定时检测会调用真实上游，消耗调用额度；预览仅验证范围与配置。

## 普通分组与调度控制

普通分组支持手动和定时检测、质量状态与历史展示，仅用于诊断；前端禁用其调度控制选项，后端也校验所选来源组。

调度降权、隔离仍仅对自动不降智来源组及其匹配的模型和请求条件生效，并需同时启用全局控制和策略控制。共享账号在普通分组的检测不能授予自动调度控制权限。更改组名不重置检测证据；改变路由条件仍走既有范围变更及证据重置逻辑。

## 查看记录

- 默认显示最近 7 天，也可选择 24 小时、30 天或自定义范围；单次范围最多 180 天，实际可见数据以元数据保留期为准。
- 可按来源组名称、账号名称、完整模型名称、结果及触发来源查询。模型筛选匹配输入模型或映射后的上游模型。
- 最新检测在前，分页由服务端执行；“查看详情”显示判分、耗时、Token、估算成本、是否计入质量状态及原始回答。
- 原始回答受独立保留期约束，到期后仍可查看剩余元数据。历史记录优先展示检测时保存的来源组名称。
- 窄屏表格支持横向滚动，避免模型、组名和按钮被压缩换行。

## 糖果 + 鹈鹕双重检测（2026-10-28）

### 如何启用

1. 运维先部署私网渲染器（下节），后端设置 `QUALITY_RENDERER_URL` 和同值的 `QUALITY_RENDERER_TOKEN`，重启后端使环境变量生效。
2. 打开“质量检测配置 → 全局设置 → 视觉评审配置”，启用视觉评审，先选来源分组，再选组内评审账号，填写支持图片输入的完整模型名和实际协议、effort、tier。建议独立稳定账号。评审传输当前使用 HTTP。
3. 点击“预览”，确认有效后“保存”。改评审配置会开启新的全局控制代次，旧证据不再控制，现有隔离状态按既有新代次逻辑重建；运行中的旧代次任务不能更新新状态。
4. 新建策略选择“糖果 + 鹈鹕”，先选组、账号，再填一或两个模型。旧糖果策略可在“已配置策略”点击“升级双检测”：归档旧策略并保留历史，继承原开关，创建新策略重新累积证据，不自动批量升级。若不希望立即定时执行，升级前先停用旧策略自动检测。
5. 先手动执行一次，从“质量监控 → 检测结果”查看作品、糖果答案及详情中的四项视觉评审。确认后再按需要开启策略及全局自动检测、调度控制。

### 判分、控制和消耗

一次双检测最多3次上游调用：被测账号的糖果请求、独立鹈鹕生成请求、评审账号的一次四帧图片评审。全部计入被测策略和全局日调用额度，不额外记入评审账号的质量策略额度；消耗真实供应商额度，不生成终端用户用量账单。预览按最多3次估算，预算不足会停止后续阶段。发送意图已提交而网络失败时保守计一次，不自动重试付费调用。

- 糖果按对应版本严格解析 JSON（旧 v1 只有 `answer`；新 v2 为整数 `answer` 加字符串 `explanation`），最终答案为21且视觉四项全通过，整体才通过。解题说明仅供展示，不另行评分。
- 任一明确不合格记为未通过。结构缺失动画、校验码等也属于未达提示要求。
- 未配置评审/渲染器、超时、调用异常、截断、视觉评审 null 或无法解析，显示未判定/具体原因；不累计明确失败或恢复证据。若糖果已经明确答错，整体仍为未通过。
- 原有降权、连续3次失败隔离、冷却至少30分钟、连续2次复测通过恢复继续按策略配置生效，恢复也须双通过。自动控制仅在自动不降智来源组及精确请求条件匹配时生效；普通0.1及降智组继续只观测。
- 四帧视觉判定依赖评审模型，属于质量信号。详情保留作品、判分与原文，管理员可核对误判。估算成本采用现有价目配置；缺失字段显示“—”，TPS为输出Token除以完整阶段耗时（含等待）。

### 展示与保留期

结果页的统计和色块限定当前组/模型筛选下保留期内最近60次检测，通过率只用明确通过和未通过作分母。作品墙每页12条，糖果侧栏显示最近20条。点击色块、作品或卡片打开该条详情；完整历史在“检测记录”。账号策略标签保留原有24小时聚合，两个口径互不混称。

详情提供“糖果 / 鹈鹕 / 视觉评审”三个分项、动画、SVG源码下载、四项视觉结果、时间、分项Token/推理Token/TPS/估算费用及是否计入状态。SVG通过图像上下文展示，不作为可执行HTML插入页面。

正文、SVG、评审原文共用原有回答保留期。到期即不可读取作品，即使清理任务尚未运行；元数据继续按元数据保留期展示。普通列表不返回正文，作品接口仅返回限量的SVG。没有新增数据库结构迁移。

### 私网渲染器部署

源码位于 `deploy/quality-renderer/`，使用 Playwright Chromium。参考 `compose.example.yml`，将其中 `quality-renderer` 服务合并到现有部署Compose（从deploy目录使用示例的相对build路径），与 `sub2api` 加入同一个私网；不发布8091到公网。设置随机共享Token，后端和渲染器使用相同值。为现有 `sub2api.environment` 增加：

```yaml
QUALITY_RENDERER_URL: http://quality-renderer:8091
QUALITY_RENDERER_TOKEN: ${QUALITY_RENDERER_TOKEN}
```

可以从仓库 `deploy/` 目录使用示例作为覆盖文件（共享Token放现有 `.env`）：

```sh
docker compose -f docker-compose.yml -f quality-renderer/compose.example.yml build quality-renderer
docker compose -f docker-compose.yml -f quality-renderer/compose.example.yml up -d --no-deps quality-renderer
docker compose -f docker-compose.yml -f quality-renderer/compose.example.yml up -d --no-deps sub2api
```

前提是主文件已经引用本次构建的新后端镜像；请保留你部署时原有的Compose文件和覆盖参数。示例直接接入现有 `sub2api-network`，改过网络名的部署需同步修改。最后一条会重建后端容器，应在正式发布窗口执行。`/health` 为容器内部健康检查；“地址已配置”仅表示存在配置，真正检测会检查渲染可用性。单渲染器限制1个并发、30秒渲染时限；并发冲突显示渲染失败，可由下一轮计划复测，不自动重试。容量较大时建议独立扩容渲染部署并调整限制后再测。

服务只接收安全SVG，不接收账号或API Key。禁止脚本、外部资源、网络和下载；容器限制内存、进程、只读根目录、临时目录及权限。正式部署应使用私有网络及Token，并沿用宿主容器安全策略。

### 回退

先停用自动检测与质量控制并等待任务结束，再回退应用版本；保留原数据库和历史。需要恢复糖果检测时使用保留的条件新建糖果策略（已归档旧策略不强行恢复）。旧版本不认识dual套件，回退前应归档/停用dual策略并移除评审配置；渲染器可停用。无需回滚DDL，不删除旧tag。


双检测验证结果与未验证项详见 `openai-quality-dual-check-design.md` 的“本地验收证据”。当前仅本地代码实现，未合并、提交、推送、部署或调用真实付费模型。

## 糖果详解与鹈鹕状态说明（v2）

新建检测策略默认使用含解题说明的 v2。详情的糖果分项展示完整题目、实际提示词、模型答案、Markdown 解题说明及折叠原文；表格与列表可正常排版。说明来自模型最终回答，不采集内部推理过程。正文保留期到期后，说明与原文一同不可读取；题目和分数仍可查看。

已有策略不会自动改版。进入“质量检测配置 → 已配置策略”，点击“升级含解题说明”，预览后确认。糖果单检仍为单检、双检仍为双检，原账号、模型、分组及开关继承；旧策略归档、历史保留，新证据重新累积。升级不会继承旧隔离状态，证据形成前按无证据状态调度，请在合适时段操作。旧记录只采集答案，不能事后补出模型解题说明，升级后须重新检测。

鹈鹕作品墙和详情将评审状态分开显示：

| 状态 | 含义与处理 |
| --- | --- |
| 未评审 | 尚未进行视觉判分；常见原因是未配置评审账号/模型或渲染器。详情提供进入全局配置的入口，配置后重新检测，旧记录不自动补评。 |
| 检测异常 | 生成、截图或评审调用未完成，或返回格式无效。按具体原因处理后重新检测。 |
| 评审不确定 | 评审已执行，但至少一项为 null 且没有明确不合格项，例如脚被遮挡或四帧不足以确认运动。 |
| 通过 / 未通过 | 四项均 true 为通过；任一 false 为未通过。生成阶段明确不满足动画结构要求也可为未通过。 |

视觉判定标准与独立评审提示词一致：

1. **鹈鹕形态**：长而宽的嘴、明显喉囊，普通短嘴小鸟不合格。
2. **自行车结构**：两个车轮、连贯车架、车把、曲柄踏板，可构成骑乘结构。
3. **骑乘姿态**：身体位置合理、腿脚连接自然，至少一只可见脚接触曲柄末端踏板，另一脚可被遮挡；悬空或踩车架不合格。
4. **运动协调**：四帧对比中脚随踏板运动、车轮转动，结构保持连接；只移动背景或整只鸟晃动不合格。画风、写实程度、是否用翅膀握把不计分。

本轮不放宽视觉判分和自动控制规则，也不新增 DDL。回退到不支持 v2 的应用之前，先停用并归档 v2 策略、等待任务结束，再回退；保留历史，需要时新建 v1 策略。详细说明增加输出长度，但调用次数仍为糖果单检1次、双检至多3次。
