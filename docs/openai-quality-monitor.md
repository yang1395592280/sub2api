# OpenAI 质量检测与检测记录

## 页面入口

管理员侧栏提供三个入口：

| 页面 | 路径 | 用途 |
| --- | --- | --- |
| OpenAI 质量监控 | `/admin/openai-quality` | 按账号、来源分组聚合模型策略，查看质量和控制状态，手动检测及 24 小时时间线 |
| 检测记录 | `/admin/openai-quality/records` | 按时间查看历史执行、结果、耗时及原始回答 |
| 质量检测配置 | `/admin/openai-quality/settings` | 创建策略、编辑已有规则、设置全局开关和预算 |

监控页顶部可进入全部检测记录；账号的“执行历史”按账号及来源分组筛选；模型时间线内的历史入口按策略筛选，保留该策略旧检测条件下的记录。

## 创建与执行

1. 在“质量检测配置 → 创建检测策略”选择来源分组，再选择组内账号。支持所有启用的 OpenAI 业务分组，包括普通 0.1 倍率、降智组；内部账号池通过业务来源组选择。
2. 填写一个或两个模型。同一账号的两个模型生成独立策略，分别记录结果；每批最多 100 条策略，两个模型时最多选择 50 个账号。
3. 设置检测周期、单日调用预算；协议、传输、推理强度和高级规则按需展开。当前检测仍使用糖果逻辑题及严格 JSON 判分。
4. 先“预览影响”，再“保存策略”或“保存并检测”。修改选择或参数后需要重新预览。
5. 需要定时执行时，同时启用策略的“自动检测”和“全局设置”中的自动检测开关。

保存并检测、立即检测以及定时检测会调用真实上游，消耗调用额度；预览仅验证范围与配置。

## 普通分组与调度控制

普通分组支持手动和定时检测、质量状态与历史展示，仅用于诊断；前端禁用其调度控制选项，后端也校验所选来源组。

调度降权、隔离仍仅对自动不降智来源组及其匹配的模型和请求条件生效，并需同时启用全局控制和策略控制。共享账号在普通分组的检测不能授予自动调度控制权限。更改组名不重置检测证据；改变路由条件仍走既有范围变更及证据重置逻辑。

## 查看记录

- 默认显示最近 7 天，也可选择 24 小时、30 天或自定义范围；单次范围最多 180 天，实际可见数据以元数据保留期为准。
- 可按来源组名称、账号名称、完整模型名称、结果及触发来源查询。模型筛选匹配输入模型或映射后的上游模型。
- 最新检测在前，分页由服务端执行；“查看详情”显示判分、耗时、Token、估算成本、是否计入质量状态及原始回答。
- 原始回答受独立保留期约束，到期后仍可查看剩余元数据。历史记录优先展示检测时保存的来源组名称。
- 窄屏表格支持横向滚动，避免模型、组名和按钮被压缩换行。
