# 独立页面与自动不降智范围设计

版本：v1.3；日期：2026-10-28；状态：页面实现基线；两个独立页面、路由、导航、详情/事件交互和批量策略操作已接通；真实管理员浏览器验收仍待完成。业务规则以 [requirements.md](./requirements.md) 为准。

v1.2 补充：监控/配置参考已搬入开源版的信息结构和交互，源码与适配说明见 [source-reuse.md](./source-reuse.md)。Vue 页面使用现有后台布局和服务端 API，不将原始独立网站直接嵌进后台。

## 1. 页面与导航

明确新增 **两个独立后台页面**，复用现有 AppSidebar 子菜单与后台路由鉴权：

```text
后台导航
  OpenAI 质量检测
    检测监控    /admin/openai-quality
    检测配置    /admin/openai-quality/settings
```

标题区固定说明“仅检测参与自动不降智分组的账号，质量控制仅在该模式生效”。普通用户无入口，直接访问路由和 API 也拒绝。拟新增页面文件为 OpenAIQualityView.vue 和 OpenAIQualitySettingsView.vue，均按项目现有后台风格实现。

账号管理页是辅助入口，提供摘要和跳转；系统设置页只提供进入配置页的链接。配置数据保持单一来源，避免在两个地方维护相同开关。

## 2. 检测监控页

```text
OpenAI 质量检测                             [检测配置] [刷新]
生效范围：自动不降智分组

[范围内账号] [正常/未检测] [观察] [隔离/恢复中] [今日预算]
运行健康：队列/运行中任务、存储状态、最后同步时间

[来源业务组] [账号搜索] [模型] [状态] [新鲜度] [参与资格]
[批量检测] [查看历史]                         （选中项操作）

账号 | 来源组/号池 | 模型/条件 | 质量状态 | 控制状态 | 最近结果 | 操作
...

[当前状态] [执行历史] [状态事件]               （内容页签）
```

- 默认每策略一行，账号可合并展开；来源组只是范围内筛选，不是任意选择固定组启控。
- 卡片展示当前可检测库存与已配置范围的差异；未配置、证据过期、检测异常不能合成“正常”。
- 同一账号挂多个来源/共享号池时列出去重后的来源，检测与预算按唯一有效策略计数。
- 操作包括立即检测、到期复测、查看详情、编辑策略、人工解除、取消任务；按状态和权限可用。
- 历史筛选支持账号/模型/来源上下文、时间、触发类型、运行状态、作答结果；状态事件可追到证据记录。
- 点击结果打开详情抽屉，展示原始最终回答、判分原因、耗时/用量、是否参与当前状态，以及仅在自动模式生效的说明。
- 复用开源版 24H 色块时间线/图例，每块可下钻到一个或多个检测结果。正式页面渲染 /policies/:id/monitor 的完整聚合，保留已移植模块的时间桶/计数口径；不得把一页历史传入 buildQualityMonitor 就标完整24H。通过率、有效覆盖和调用异常分开展示。
- 账号已移出范围时显示“停止参与，检测/控制暂停”，保留历史，禁止继续发检测。来源上下文失效时引导替换策略重新检测。
- 活动任务轮询2–5秒退避，任务终态停止短轮询；空闲概览建议30秒刷新。页面隐藏暂停，刷新不触发模型调用。

### 2.1 监控数据与下钻

首屏分别请求 /overview（全部筛选策略概览）和 /policies（分页行）；展开某策略后才取 /monitor，点击结果才取正文。账号计数、策略计数与全局预算各标分母，不能相加成一个“健康账号数”。来源筛选按兼容来源去重，不重复计共享池账号。

时间线固定显示“服务端统计时间、当前范围、当前代次”，可切换“当前范围全部代次历史”；后者明确含旧观察数据，不能与当前状态计数混同。色块样本ID最多5个，点开后分页获取全部记录；不把示例ID数当时隙总任务数。默认普通周期1800秒为48桶，最细300秒最多288桶。

保留开源图例、键盘可聚焦的时隙按钮和文字提示，不只靠红绿颜色区分。加载中展示占位，空样本显示“暂无检测记录/—”，读取失败保留上次图并标过期和重试；无有效答案的通过率为“—”，不是0%或100%。切换筛选/账号丢弃旧异步回包。

下钻基于固定时间边界，不是永久历史快照；任务执行/清理造成变化时提示刷新统计。下钻不是再触发检测。对已不在范围的策略，保留历史入口，禁用运行与启控。

## 3. 检测配置页

```text
检测配置                                    [返回监控]
生效范围：自动不降智分组（只读）

全局设置
  自动检测总开关 [关]        调度控制总开关 [关]
  集群并发 / 队列 / 每日预算 / 回答保留 / 历史保留
  [预览影响] [保存全局配置] [紧急停用自动与控制]

检测策略
  [范围内来源组筛选] [添加/批量配置策略]
  账号 | 有效来源上下文 | 模型与条件 | 周期 | 阈值 | 开关 | 操作

策略编辑
  账号与有效来源组（创建后更换需显式替换）
  模型 / HTTP或WS / effort / 档位 / 内置题版本
  自动检测周期 / 抖动 / 输出上限 / 超时 / 单策略日预算
  错误阈值 / 证据窗口 / 最短冷却 / 恢复周期 / 恢复阈值
  策略自动开关 / 策略控制开关
  [预览] [保存] [保存并检测]
```

- 全局设置与策略使用各自 revision，保存范围清楚，避免保存其中一块覆盖另一块。
- 账号选择器只显示 GET /targets 返回的合格账号；来源上下文选择器只列该账号可以通过的自动业务来源组，自建池显示为物理来源。
- 保存前展示 requested/effective 条件差异、能力缺失、重复范围冲突、预计日调用数和预算缺口。全局默认预算不能支撑所有策略时明确提示。
- 启控时展示新代次从未检测开始；既有观察风险单独列出，不错误承诺开启瞬间隔离旧异常账号。
- “暂停自动检测”保留当前控制，“关闭控制”退出质量调度，“人工解除”重置状态；三者在文案与操作上分开。
- 冷却到期表示可以累计恢复证据，不能显示成“预计此时自动恢复”。
- can_probe/can_enforce 不支持时展示具体原因，不能通过强制提交表单保存启控。
- 保存并检测为两步：保存成功后提交异步任务，第二步失败只显示检测提交失败，保留已保存配置。

### 3.1 配置页必须展示的生效说明

全局默认策略日预算标“仅新建策略使用”；每策略显示实际保存值。批量编辑先选择策略，展示数量和新旧差异，不随全局默认变动悄悄更新既有策略。保存并检测可以在自动关闭时使用，但必须明确这是一次付费任务提交。

预览区分硬错误与警告：不支持条件、重复范围、窗口容不下阈值样本阻止保存；预算不足、队列/抖动导致窗口余量不足允许保存并显著提示。显示计划基础调用数、当前启用调用数、全局/策略额度和理论预算覆盖；不是只显示“配置有效”。100策略/30min的4800/日需求与1000上限、可能无法累积阈值的后果都可见。

开控制但未开自动时，显示“仅手动检测，隔离后不会自动复测”；暂停自动但仍隔离时持续显示阻塞原因。修改阈值不即时回放历史、修改冷却不改变本次cooldown_until、缩短保留期可能清理旧正文，均在对应字段旁说明。具体语义见 [配置变更矩阵](./implementation-guide.md#3-配置变更的生效规则)。

启控/关闭/解除/归档/紧急停用使用项目既有确认交互说明真实影响，提交后以服务端返回状态为准；不得先把按钮置成功，再掩盖写入失败。未保存表单离开页面使用现有表单习惯提示，不新造审批流。

## 4. 自动不降智识别与共享账号边界

项目现有前端值为 `openai_auto_cheapest`，后端判断为 `UsesOpenAIAutoCheapestGroup()`；不能依赖名称字符串，也不能将任意 OpenAI 普通组视为“不降智组”。

| 场景 | 发起本需求检测 | 应用本质量控制 |
| --- | --- | --- |
| 活跃 OpenAI 自动来源组中的账号，已有策略 | 手动/自动/恢复按开关及预算执行 | 仅原始自动不降智请求 |
| 自动来源组引用的自建池账号 | 纳入库存、按有效条件去重 | 仅该池被自动不降智请求引用时 |
| 同一账号同时绑定普通固定组 | 不为固定组另外发检测 | 固定组不降权、不隔离 |
| 仅存在于普通固定组的账号 | 不允许新建/运行 | 不应用 |
| 独立 composite 或其他平台 | 不纳入 | 不应用 |
| 账号移出全部有效自动来源 | 停止新任务，保留历史 | 不再应用；重新参与需新证据 |
| 自动模式内部切换实际业务组/池 | 不按每次请求发检测 | 保留原始模式标记，继续执行质量门 |

检测是后台独立任务，不按用户请求同步跑题。管理员库存不是权限授予；每次真实选择仍使用现有用户可用组、最高倍率、模型能力等限制。

## 5. 资格变化与空/错状态

- 无自动来源或无可检测账号：监控页显示范围为空，引导检查现有参与自动调度配置，不扫描普通固定组兜底。
- 已有来源但无策略：显示“尚未配置检测”，提供进入配置页入口；不自动批量扣费。
- 账号移出范围/来源上下文失效：保留状态与历史，停止任务和控制，重新配置后建立新证据。
- 预算不足/限流/不支持：解释检测受阻；不把受阻标为正常或答案错误。
- 状态存储故障：显示最近同步与数据有效性；关闭失败必须说明未成功，不把按钮视觉状态作为全实例已停用证据。
- 任何状态说明都标“仅自动不降智生效”；对普通固定组的既有真实凭据/额度/限流保护不作虚假的完全独立保证。

## 6. 本版验收补充

两个独立路由和导航存在；配置可完整保存/回显且与监控互相跳转；范围外账号无新任务；同账号 auto 请求隔离、fixed 请求保持原逻辑；auto 内切组/WS turn 不丢模式；来源移除/重新加入不继承过期控制。具体场景编号见 [验收规范](./specs/account-quality-control/spec.md)。
