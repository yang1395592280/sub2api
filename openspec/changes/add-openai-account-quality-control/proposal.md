# OpenAI / Codex 账号质量检测与调度控制提案

日期：2026-10-28；版本：v1.3；状态：**核心本地实现已接通，集成验收进行中；检测和控制默认关闭**。基线：`96f8b5034`（`v0.2.18.1`）。入口见 [README.md](./README.md)，实际验证见 [verification.md](./verification.md#11-本地实现与验证-2026-10-28)。

## Why

当前账号测试主要证明请求完成，无法解释“网络正常但持续答错”；已有鹈鹕批量测试只有生成/预览，没有回答质量判定。管理员希望逐个检测 OpenAI / Codex 上游账号，在指定条件持续错误时降权、隔离，再经复测恢复。

manxue.ai 存在相关 [Apache-2.0 开源项目](https://github.com/w1196396546/manxue-ai)，但不能据此认定现站全部实现开源。前序核验发现开源视觉审核与现站源码分类器不同；直接照搬不能获得相同评分能力。推荐在 sub2api 内定向调用账号并本地判分，首期采用前提明确、答案可独立验证的糖果题。

## What Changes

- 增加按账号、有效模型、协议/传输、effort、服务档位、路由身份及题目版本区分的检测策略。
- 手动/自动/恢复任务共用集群并发和预算；运行状态、作答质量、质量状态、新鲜度分别表达。
- 建议默认观察；连续 3 次有效错误隔离，最短 30 分钟冷却后连续 2 次有效复测通过恢复。全部数值均待评审，可配置。
- 检测与控制限定为既有自动不降智模式 openai_auto_cheapest；只检测参与该模式的账号，同账号普通固定组不受本质量状态影响。
- 不改写原始 Priority，在自动模式内的原健康阶段先全来源基准池、后观察池；精确隔离覆盖该模式的新旧调度、备用来源、会话及 WS 后续 turn。
- 建立策略、执行、事件、每日预算四张独立表，复用设置、鉴权、审计和既有幂等表；默认不回填账号，不产生用户扣费。
- 新增两个独立后台页面“检测监控”“检测配置”，提供全局/策略设置、账号摘要、批量操作、历史、影响预览及人工解除。
- 复用开源版已有监控/配置与检测代码，固定原始版本和许可；已移植时间线/统计数据模块，完整来源映射见 source-reuse.md。
- 监控使用全量概览和单策略24H聚合，不依赖历史分页；补齐有限时间桶下钻、配置生效矩阵和预算/证据窗口可达性，完整接线与端到端示例见 [implementation-guide.md](./implementation-guide.md)。

## Impact

涉及数据库结构、新管理接口、后台任务、共享调度和传输准入。实现后开启会产生模型调用成本，错误隔离/存储故障可能降低可用性。单题不能证明模型身份或总体智能水平，需实际条件观察校准。

全局自动/控制与策略自动/控制开关均默认关闭。建议全隔离返回明确 503；无可信质量快照时对开启控制范围拒绝，保留已知隔离。停测不自动解除隔离，冷却到期不自动恢复，启控不追溯旧观察记录。

## Non-goals

不取得未知分类器、不向第三方提交凭据、不自动改价或人工账号状态、不扩展其他平台、不承诺“满血鉴定”。本轮仅引入开源代码和移植监控数据计算，未接真实后台或执行数据库迁移、真实模型调用、部署、启控、提交或 push。

## Status 与评审事项

已完成网站/相关开源核验、现有代码能力核对，以及完整需求、技术设计、API、页面、分阶段任务和验收规范。已确认逐账号降权/隔离/复测方向；用户本轮明确只对“不降智分组”检测处理，依据仓库现有标识落实为自动不降智模式边界。

实现采用需求决策表 D01–D09 中的本地方案；当前代码状态和验证范围见 [verification.md](./verification.md#11-本地实现与验证-2026-10-28)。代码已接通不代表生产迁移、真实账号检测、共享调度控制启用或上线。
