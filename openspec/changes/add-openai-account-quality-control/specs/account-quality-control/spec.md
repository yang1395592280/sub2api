# 账号质量控制验收规范

状态：v1.3 需求与验收基线；核心本地代码已接通，场景尚未全部验证。规则来源：[requirements.md](../../requirements.md)；接口来源：[api-contract.md](../../api-contract.md)；页面见 [ui-design.md](../../ui-design.md)，实施串联见 [集成指南](../../implementation-guide.md)。SHALL/MUST 表示所需行为，不代表生产已部署或启用。

## ADDED Requirements

### Requirement Q01：策略准确绑定账号与有效请求条件

系统 SHALL 只为管理员明确选择、参与现有自动不降智模式的 OpenAI / Codex 逻辑账号创建策略，按真实上游有效模型、协议、传输、effort、服务档位和路由身份建立请求范围，按题目/评分版本建立证据范围。相同请求范围 MUST 只有一个活动策略。

#### Scenario Q01-01：批量保存具有事务性
- **WHEN** 100 项以内的创建/更新中至少一项无效、范围冲突或 revision 过期
- **THEN** 所有项 MUST 不落库，并提供可定位项和原因
- **THEN** 不发送模型请求，不扣检测预算

#### Scenario Q01-02：模型与有效条件映射
- **WHEN** 公开别名映射到账号模型，且 effort/tier 被项目既有规则强制映射
- **THEN** 探测快照和真实转发 MUST 使用同一归一化结果
- **THEN** low 的证据不得影响有效 high，不同协议/传输不得默认共享证据

#### Scenario Q01-03：身份与配置漂移
- **WHEN** 上游地址、代理、模型映射或实际凭据身份发生变化
- **THEN** 旧证据 MUST 失效、旧任务不得更新新状态，并安排新范围检测
- **THEN** 正常 OAuth Token 刷新若身份未变，不得因 Token 字节变化抹掉证据

#### Scenario Q01-04：影子账号与重复题目
- **WHEN** 母账号和影子账号复用凭据，或相同请求范围试图创建另一题目版本
- **THEN** 两个逻辑账号 MUST 不自动传播结果
- **THEN** 同一逻辑账号相同请求范围的第二活动策略 MUST 被拒绝或显式原子替换

#### Scenario Q01-05：来源库存与资格变化
- **WHEN** 账号仅在普通固定组，或来源停止活跃/禁止参与自动调度/引用号池失效
- **THEN** 创建和执行必须校验；不满足参与资格时不得发手动、定时或恢复探测
- **THEN** 已有策略暂停并保留历史；移出后重新加入必须重建证据，不复活旧隔离
- **THEN** 对多来源共用同账号/有效条件去重，不按每个用户或 Key 重复检测；来源组上下文不得由任意固定组伪造

#### Scenario Q01-06：默认值不是动态继承
- **WHEN** 策略11以全局默认日预算100创建，随后默认值改为200，并新建策略12
- **THEN** 11仍为100、12缺省为200；既有策略不被批量改写，所有策略仍受全局日额度约束
- **THEN** 批量编辑必须明确选中策略、携带完整规则和revision，不能因更改默认值重置控制代次

### Requirement Q02：检测是独立、定向、有界的后台任务

系统 SHALL 支持手动、定时、恢复三种来源，指定账号直连上游；MUST NOT 经公网 API Key 随机调度、带用户会话绑定或提交凭据给第三方。

#### Scenario Q02-01：自动关闭时手动运行
- **WHEN** 全局和策略自动检测关闭，管理员显式提交手动任务
- **THEN** 系统 MUST 返回 202 和每项受理结果，页面关闭后任务仍可查询
- **THEN** 不因自动关闭拒绝合法手动诊断

#### Scenario Q02-02：多实例重叠扫描
- **WHEN** 多个实例同时扫描同一到期策略
- **THEN** 同一个 scheduled_slot MUST 至多创建一个任务，同策略至多一个活动任务
- **THEN** 同一逻辑账号至多一个 running，集群 running 不超过配置上限
- **THEN** 网络调用期间 MUST 不持有事务行锁或全局 advisory lock

#### Scenario Q02-03：排队、超时与受理未知
- **WHEN** 队列超时、账号繁忙、调用超时或 worker 在发出后崩溃
- **THEN** 分别记录 skipped/error/interrupted 等真实结果，不记 incorrect
- **THEN** 不补发错过的周期，不自动重放受理情况未知的付费 POST

#### Scenario Q02-04：取消与租约
- **WHEN** queued 被取消，或 running 被请求取消/租约失效
- **THEN** 未发出任务不得随后发出；正在执行的调用协作取消
- **THEN** 旧 lease_token 的迟到回调 MUST 无权覆盖终态或当前聚合

#### Scenario Q02-05：自动开关与出站并发
- **WHEN** 全局或策略自动关闭，与scheduled/recovery任务的dispatch意图事务并发
- **THEN** 关闭先提交时未出站任务必须取消，不再发送；dispatch先提交的调用有界完成，不承诺撤销费用
- **THEN** 手动任务不因全局自动关闭被拒绝；版本不匹配的结果只保留历史，停测不解除隔离

### Requirement Q03：只用确定的最终答案判分

系统 SHALL 使用版本化 candy-v1 和 strict-json-v1；MUST 区分作答质量和可用性。业务请求完成不等于质量通过。

#### Scenario Q03-01：题意与标准答案独立验证
- **WHEN** 题目明确允许事前固定两种形状数量、无法辨口味
- **THEN** 标准答案 MUST 为 21，存在圆形 9/五角星 12 的保证方案，任何总数 ≤20 的方案均不保证
- **THEN** 完全无法控制形状的另一题答案 29 MUST 不被混入此版本

#### Scenario Q03-02：严格 JSON 边界
- **WHEN** 返回纯 `{"answer":21}` 或一个合法围栏包裹的同一对象
- **THEN** 结果 MUST 为 passed
- **WHEN** 返回唯一合法整数 20
- **THEN** 结果 MUST 为 incorrect
- **WHEN** 返回字符串、小数/指数写法、重复 answer 键、额外字段、多份 JSON、混合正文或超出有符号 64 位整数
- **THEN** 结果 MUST 为 unknown，而非通过或答案错误

#### Scenario Q03-03：提到正确数字不等于通过
- **WHEN** 输出解释中包含 21，最终内容不符合唯一 JSON 或答案错误
- **THEN** 系统 MUST NOT 用数字正则判为通过；混合正文记 unknown

#### Scenario Q03-04：异常分流
- **WHEN** 输出空白、拒绝、未完成、截断、过长或条件 unsupported
- **THEN** verdict MUST 为 unknown，并保留稳定原因
- **WHEN** 出现超时、401、429、5xx、HTTP/WS 传输错误
- **THEN** verdict MUST 为 error；不增减有效答案计数

### Requirement Q04：状态、新鲜度与控制代次独立表达

系统 SHALL 分别维护任务运行状态、verdict、质量状态和 freshness。控制开关开启 MUST 建立新代次，旧观察历史 MUST 不被追溯成真实隔离。

#### Scenario Q04-01：默认状态序列
- **WHEN** 在同一窗口/范围/代次内依次得到 incorrect、incorrect、incorrect
- **THEN** 默认状态 MUST 依次为 observing、observing、quarantined
- **WHEN** 未隔离时得到 passed
- **THEN** 清零失败计数，置 normal

#### Scenario Q04-02：夹杂异常与窗口过期
- **WHEN** 有效错误之间夹杂 unknown/error
- **THEN** 不增加也不清零连续有效错误，但只统计当前 120 分钟窗口内的样本
- **WHEN** observing 证据过期
- **THEN** 软降权 MUST 停止，页面显示过期，下一有效样本按剩余窗口证据累计
- **WHEN** 已隔离的证据过期
- **THEN** MUST 继续隔离，不能按 TTL 恢复

#### Scenario Q04-03：开关代次隔离
- **WHEN** 观察模式已有三次错误，再打开全局或策略控制
- **THEN** 当前控制状态 MUST 为 untested，旧样本仅展示在历史
- **THEN** 只有新代次的有效样本才能降权或隔离；旧 worker 不得带入旧证据

#### Scenario Q04-04：阈值和规则编辑
- **WHEN** 调高失败阈值或修改恢复阈值
- **THEN** 保存动作不得即时回放旧历史改变隔离；已隔离不能靠调高阈值解除
- **THEN** 下一有效样本按新规则归约；参数阈值为 1 的直接隔离/恢复路径 MUST 覆盖

#### Scenario Q04-05：窗口与当前冷却的编辑
- **WHEN** 当前隔离cooldown_until已确定，管理员缩短或延长冷却配置
- **THEN** 当前cooldown_until必须保持，下一次进入隔离才使用新冷却参数
- **WHEN** 缩短证据窗口使observing证据过期
- **THEN** 新鲜度/软惩罚按新窗口处理，但已quarantined/recovering不得因此解除

### Requirement Q05：降权保持现有调度阶段和管理员配置

系统 SHALL 只在自动不降智模式的每个原健康选号阶段先扫描全来源基准池、再扫描观察池；MUST 保留池内原排序、来源授权/最高倍率边界、账号原始 Priority、价格与倍率。

#### Scenario Q05-01：基准与后备池
- **WHEN** 新请求同时有基础合格正常/未检测账号与新鲜观察账号
- **THEN** MUST 优先基准池；基准池都不可选时允许观察池
- **THEN** 原始 Priority 不发生数据库写回

#### Scenario Q05-02：自动不降智与备用来源
- **WHEN** 相同原健康阶段中廉价来源只有观察账号，较贵且授权/倍率允许的来源有正常账号
- **THEN** MUST 优先跨来源基准池，不恢复廉价来源宽松先于其他来源达标的旧策略
- **WHEN** 所有基准池为空
- **THEN** 可按原健康阶段/严格故障切换限制尝试观察后备，各阶段不得放行隔离账号
- **THEN** 质量拒绝不得当成上游失败污染原有账号/组熔断计数

#### Scenario Q05-03：质量优先不扩大来源权限
- **WHEN** API Key最高倍率0.2，合法0.1来源仅有观察账号，而0.3来源有正常账号
- **THEN** 0.3来源仍不能进入候选；在原健康阶段和授权限制内使用观察后备，或保留原基础失败原因
- **THEN** 不得借“优先正常账号”越过最高倍率、用户来源授权或严格故障切换限制

### Requirement Q06：隔离、最短冷却与恢复形成闭环

系统 SHALL 在匹配范围对隔离账号拒绝新准入，并使用专用恢复探测。质量通过 MUST 不解除账号其他限制。

#### Scenario Q06-01：冷却不是恢复
- **WHEN** 隔离后 30 分钟尚未到期，手动检测 passed
- **THEN** 仅记录诊断，不积累恢复次数
- **WHEN** 冷却到期但没有有效复测
- **THEN** 仍隔离，不按时间自动放行

#### Scenario Q06-02：默认恢复序列
- **WHEN** 冷却后依次得到 passed、unknown、passed，两个有效样本在窗口内
- **THEN** 状态 MUST 为 recovering、recovering、normal；直到最后一步才解除限制
- **WHEN** 恢复期间得到 incorrect
- **THEN** 清零恢复计数，重启最短冷却
- **WHEN** passed 之间超出证据窗口
- **THEN** 旧恢复通过不计数，不足阈值继续隔离

#### Scenario Q06-03：人工解除与晚到任务
- **WHEN** 管理员填写原因解除隔离
- **THEN** 状态 MUST 为 untested，并推进代次；不显示“复测正常”
- **THEN** 旧任务完成仍保留历史，但 state_applied=false，不得重新隔离或恢复

#### Scenario Q06-04：真实硬限制保留
- **WHEN** 账号人工禁用、schedulable=false、已过期或基础额度不足
- **THEN** 即使质量 passed 也 MUST 不成为可用账号
- **THEN** 专用恢复探测只豁免质量隔离，不豁免以上硬限制

### Requirement Q07：管理员能完成配置、解释与处置

界面 SHALL 新增两个独立后台页面“检测监控”“检测配置”，并提供账号快捷入口、按条件质量摘要、详情/历史与处置；不能仅显示一个模糊“满血/降智”标识。

#### Scenario Q07-01：配置与预算预览
- **WHEN** 创建 100 个每 30 分钟自动检测的策略
- **THEN** MUST 显示基础 4,800 次/天与默认全局 1,000 次的冲突
- **THEN** 可检测/可控制能力缺失时解释原因，禁止开启该范围控制

#### Scenario Q07-02：多模型与历史详情
- **WHEN** 同账号一个条件正常、另一个隔离、另一个证据过期
- **THEN** MUST 展示混合状态并可展开条件，不给出整个账号“全部正常”结论
- **THEN** 历史区分运行/作答，正文只在详情按需读取并安全转义

#### Scenario Q07-03：操作的实际含义
- **WHEN** 暂停自动、关闭控制、人工解除、归档、取消任务
- **THEN** 分别解释是否继续隔离/是否仍会收费；保存成功但检测提交失败要分别反馈
- **THEN** 页面隐藏暂停轮询、任务终态停止轮询；中英文文案齐全

#### Scenario Q07-04：独立页面和范围可见
- **WHEN** 管理员打开 /admin/openai-quality 与 /admin/openai-quality/settings
- **THEN** 分别提供监控/历史/处置与全局/策略完整配置，两页通过导航和上下文互相跳转
- **THEN** 顶部固定标“仅自动不降智生效”，账号选择只来自合格库存，系统设置仅跳转不维护重复配置
- **THEN** 普通用户无入口且直接访问拒绝；仅普通固定组账号显示“不在检测范围”

#### Scenario Q07-05：开源监控复用可追踪
- **WHEN** 复用开源项目的监控/配置页面和检测代码
- **THEN** 固定来源提交、保留许可/归属/原文件清单，在修改文件中说明适配；页面接入原版已有时间线/历史交互，不重复维护独立认证/访客 Key 入口
- **THEN** 时间线按策略/证据范围隔离、记录去重，点击时隙可查看全部记录；通过率只按有效答案统计，调用异常单列
- **THEN** 原版含 21 的正则判分不得被误用于自动隔离，不把源码搬入表述成页面/控制已完成

#### Scenario Q07-06：完整24H聚合不依赖历史页
- **WHEN** 当前策略24H有超过100条记录，而/runs第一页仅20条，且同时存在旧scope/旧epoch记录
- **THEN** /monitor必须完整统计当前选择的scope/epoch，/overview聚合全部筛选策略；不得拿第一页算完整通过率
- **THEN** 默认当前代次；切换current_scope明确标含旧历史，旧样本不参与当前控制，summary和桶来自同一数据库快照

#### Scenario Q07-07：有限时间桶与完整下钻
- **WHEN** 选择300秒粒度，某桶含超过5条记录，且有记录恰好在窗口起点、桶边界或as_of
- **THEN** 最多288桶，每条符合条件的记录恰计一次；最后桶含as_of，未来记录排除
- **THEN** 每桶全量计数、sample_run_ids最多5个；点击后可分页查看全部记录，不能只展示样本ID
- **THEN** as_of只是边界，后续running变化/清理可提示刷新；不得维持跨请求长事务冒充永久快照

#### Scenario Q07-08：异步回包和监控故障
- **WHEN** 切换策略/筛选后旧请求才返回，或监控聚合读取失败
- **THEN** 旧回包不得覆盖新选择；失败必须显示不可用/过期，不返回或展示伪造的complete=true空图
- **THEN** 没有有效分母显示“—”；账号数/策略数/全局预算口径清楚，页面隐藏不持续轮询

### Requirement Q08：成本与容量有集群级上限

系统 SHALL 共享预算约束手动/定时/恢复任务，使用既有账号容量，独立记录运营成本；MUST NOT 创建用户账单或污染业务成功/速度统计。

#### Scenario Q08-01：预算竞争与取消
- **WHEN** 多实例同时竞争当天最后一个全局/策略名额
- **THEN** 最多一个预留成功；全局与策略预算不得部分提交
- **THEN** 未发出取消最多释放一次；已发出/受理未知仍计消费，不因错误退款

#### Scenario Q08-02：时区、缺失用量与输出上限
- **WHEN** 跨自然日、实例时钟偏差、上游无 usage 或不支持硬输出上限
- **THEN** 预算日期以数据库时间和实例一致时区确定，出站时重新校验预算日期
- **THEN** 无 usage 存 null，不支持上限必须显示局限，不宣称绝对费用封顶

#### Scenario Q08-03：业务资源和统计隔离
- **WHEN** 质量探测耗时长、成功或被限流
- **THEN** 不记为真实业务成功/慢请求，不扣用户余额；必要认证/429 保护仍按原机制执行
- **THEN** 繁忙账号延后探测，释放所有已取得的并发资源

#### Scenario Q08-04：窗口可达性和预算不足
- **WHEN** F=10、I=1800秒、W=7200秒，或恢复阈值对应理想跨度超过窗口
- **THEN** 预览与保存必须一致拒绝，指出evidence_window_seconds，不能靠增加预算绕过
- **WHEN** 100策略/30min且全局1000次/日
- **THEN** 显示4800次基础需求、约20.83%理论预算覆盖、公平均摊约144min间隔与120min窗口的风险；允许带警告保存
- **THEN** 不自动改阈值、窗口、策略数或预算；18策略864次/日的136余量不能宣称为恢复保留

### Requirement Q09：结果、状态与事件在一致事务中生效

系统 SHALL 对终态、预算、聚合、状态事件做原子提交，并对策略 revision、范围、代次和租约进行 fencing。

#### Scenario Q09-01：并发完成/人工操作
- **WHEN** 同一结果重复回调、解除与完成竞态、修改与完成竞态
- **THEN** 终态/预算/状态事件只提交一次，旧条件结果保留但不能更新新状态
- **THEN** 缓存只在提交后失效，不可先把内存恢复结果用于放行

#### Scenario Q09-02：幂等崩溃窗口
- **WHEN** 管理端断网重试同 key 同请求，或业务提交后幂等响应登记前进程崩溃
- **THEN** 不得形成重复活动任务/双重预算消费，返回原任务或明确冲突/处理中
- **WHEN** 同 key 不同请求体，或幂等 coordinator 未初始化/存储不可用
- **THEN** 分别冲突/拒绝，不通过 helper 的降级分支产生新付费任务

#### Scenario Q09-03：规则更新和任务失效
- **WHEN** 编辑规则与任务出站/完成并发
- **THEN** 保存时同事务推进revision、重算排期并取消旧revision未出站任务；已出站结果只保留历史，不能更改当前状态
- **THEN** 下一有效样本可按新规则使用此前已接受的同scope/epoch窗口内证据；保存本身不触发隔离/恢复
- **THEN** 降低并发不终止在途调用，降低预算时未出站任务重新核验，缩短保留期不删除活动任务/当前状态

### Requirement Q10：权限与敏感数据边界保持真实

系统 SHALL 沿用 IsAdmin 管理员角色与现有鉴权；首期 MUST 拒绝普通用户和受限管理 Key 的所有质量路由，不引入虚构角色。

#### Scenario Q10-01：逐接口鉴权
- **WHEN** 使用普通用户 JWT、受限管理 Key 访问设置/能力/历史/正文/运行/解除等任意路由
- **THEN** MUST 403，不产生副作用；仅隐藏按钮不能视为合格

#### Scenario Q10-02：秘密与审计
- **WHEN** 调用返回含敏感上游内容或进行管理变更
- **THEN** 凭据 MUST 不出现在数据库快照、API、审计、日志和第三方；正文限长、脱敏、纯文本展示
- **THEN** 操作原因与主体、状态证据、控制代次可追踪，异步审计失败不得替代状态事件事务

### Requirement Q11：故障语义、会话安全与回退可解释

系统 SHALL 在原始自动不降智模式内覆盖新调度、legacy、来源切换、session、response-owner、WS 握手/后续 turn 及抢槽后发送前终检。MUST 不换账号转发不可迁移 ID，不拼接已经输出的请求；固定组与独立 composite 不纳入本质量门。

#### Scenario Q11-01：不可迁移绑定
- **WHEN** previous_response_id 的归属账号被隔离，或 WS 下一 turn 准入时发现隔离
- **THEN** MUST 返回 QUALITY_SESSION_RESTART_REQUIRED 或对应 WS 错误，不将原 ID 交给其他账号
- **THEN** 已开始的 turn 不追溯拼接/取消，后续 turn 继续检查

#### Scenario Q11-02：调度旁路
- **WHEN** 自动不降智请求关闭旧自动评分、命中 sticky、使用引用的自建池/备用来源或切换实际业务组
- **THEN** 匹配质量隔离 MUST 仍成立；抢槽后隔离发生时终检拒绝且释放资源
- **THEN** 专用探测的豁免标记 MUST 不能从公网输入启用

#### Scenario Q11-03：全隔离与存储故障
- **WHEN** 基础合格候选都因质量隔离不可用
- **THEN** 返回 503 QUALITY_NO_ELIGIBLE_ACCOUNTS，不返回正常空流或静默放行
- **WHEN** 已知隔离快照遇到存储故障
- **THEN** 继续拒绝；无可信快照或正常快照故障超过 60 秒，开启控制范围返回 QUALITY_STATE_UNAVAILABLE
- **THEN** 纯基础不可用错误保留原原因，不能误报质量错误

#### Scenario Q11-04：默认关闭、紧急关闭与重启
- **WHEN** 两层控制均关闭且设置已可信加载
- **THEN** 真实请求不读取质量表，既有选路/用量/普通定时测试兼容
- **WHEN** 紧急关闭成功
- **THEN** 两个全局开关原子关闭，正常依赖环境下 5 秒内所有实例退出质量门
- **WHEN** 数据库不可写导致关闭失败，或重启无法读取设置
- **THEN** MUST 显示真实失败/初始化不可用，不能将读失败视为默认关闭

#### Scenario Q11-05：版本回退
- **WHEN** 在测试环境演练新增 forward-only 迁移及回退旧应用
- **THEN** 不修改旧迁移校验值、不执行内嵌 Down SQL、不删除历史；先停控再回退
- **THEN** 明确旧版不识别质量隔离，不声称回退后仍有保护

#### Scenario Q11-06：同账号在自动与固定组的隔离边界
- **WHEN** 同一账号/模型/条件在自动不降智模式中被质量隔离，但固定组仍满足原基础条件
- **THEN** auto 请求 MUST 拒绝该账号，fixed 请求 MUST 沿用原逻辑且不读取本质量快照
- **THEN** 不写账号全局禁用/质量限流状态；独立 composite 同样不因本质量状态被拒绝

#### Scenario Q11-07：原始模式在内部切组和 WS 中保留
- **WHEN** 自动不降智请求被克隆成有实际 GroupID 的 effectiveKey、重试切组或执行 WS 后续 turn
- **THEN** MUST 保留原始 auto 范围标记，不得误判为固定组后绕过质量门
- **THEN** 客户端不能通过自带字段/请求头把固定组升级成 auto 或启用探测豁免；所有真实授权仍按原规则校验

### Requirement Q12：效果和性能用证据验收

系统 SHALL 提供有效判分率、条件覆盖、预算、状态与调度拒绝指标；在本地可重复环境测试功能与性能，再单独批准真实账号观察/启控。

#### Scenario Q12-01：统计分母与过期证据
- **WHEN** 结果为 3 passed、1 incorrect、56 error
- **THEN** 通过率为 75%，有效判分为 4/60；MUST NOT 展示“可用率 75%”或所有账号均健康
- **THEN** 正常状态证据过期或 unknown 持续时展示覆盖不足

#### Scenario Q12-02：性能与容量
- **WHEN** 100 候选/1,000 活动策略的可重复并发基准执行
- **THEN** 缓存命中新增选号 P95 目标 ≤5 ms，每次选号批量回源 ≤1，回源超时目标 ≤100 ms
- **THEN** 用实际结果验收，不拿旧版单元测试代替性能证明；正文/元数据清理不删除活跃任务或当前隔离快照

#### Scenario Q12-03：真实效果边界
- **WHEN** 尚无目标账号实际观察样本，或单题已被记忆/格式覆盖不足
- **THEN** 交付 MUST 标记检测效果尚未验证，不能宣称可靠识别所有“降智”或模型真伪
- **THEN** 阈值和题目上线前先小规模观察校准，不自动启动真实批量调用

#### Scenario Q12-04：端到端示例的可复现验收
- **WHEN** 使用假时钟和本地上游桩执行集成指南§5的观察、启控、三错、冷却前通过、冷却后两次通过
- **THEN** 每一步的任务/状态/事件/调度结果与示例一致；恢复先持久化再放行，同账号fixed请求沿原逻辑
- **THEN** 该桩验证不得称为真实模型识别效果；不自动调用真实付费模型或执行生产迁移
